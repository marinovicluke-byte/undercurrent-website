# Service pages: what each has, and where it reads as a wall

2026-10-02, branch `design/services-pages`. Before screenshots: `docs/screenshots/services-before/` (390 and 1440, production build, reduced motion so every section shows).

## How they're built

There are four routes, `app/automation`, `app/website`, `app/seo` and `app/consulting`. Each is a separate `page.js` of about 320 lines, ported verbatim from the sandbox mockups (`_sandbox/test-site/mockups/service-*.html`, commit 2fdcda0). Each has its own stylesheet, `app/styles/{automation,website,seo,consulting}.css`, and the four stylesheets are near-identical. They differ in six colour values in `:root` and in the website page's screenshot cards. Behaviour comes from `components/site/ServiceFx.js`. There are no shared section components, so a design change today means four edits to markup and four to CSS.

All four pages share the same fourteen sections in the same order. Only the copy and the colour change.
